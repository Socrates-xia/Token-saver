# 站点适配细节与已知坑

这些是实测踩出来的经验，改站点适配前建议先读一遍。

## 总览

| 站点 | 深度思考 | 生图 | 抓取难度 | 备注 |
| --- | --- | --- | --- | --- |
| DeepSeek | ✅ 有独立开关 | ❌ | 低 | 推理强，首选 |
| 豆包 | ❌ 已取消（改模型选择） | ✅ | **高** | 生图就找它 |
| Kimi | ⚠️ 无开关，可选 K3 模型 | ❌ | 中 | 长文本强 |

## 一、通用机制（改适配前务必理解）

### 四级抓取降级

答案抓取按可靠性从高到低尝试，任一级成功即停：

1. 厂商自定义选择器（快而准，但站点改版会失效）
2. ARIA 语义 / `data-testid`（较稳）
3. 通用 Markdown / 角色容器（兜底）
4. 点击"复制"按钮读剪贴板（最稳，几乎只依赖按钮文案）

### 三阶段等待

判断"回答完了没"分三步，避免把思考过程当答案、或把完成态当进行态：

1. **等开始**（最多 45s）：出现新文本 / 停止按钮 / 思考中
2. **等停止按钮消失**（带上限）：有些站点答完按钮还留着，无限等会空耗
3. **等文本稳定**：连续 N 秒不变才算完；"停止按钮可见则重置计时"只在**前 90 秒**认

### 会话续聊

- 记住话题停在哪个会话页（`chat_url`）+ 浏览器上下文的**出生时间戳**（`ctx_born`）
- 追问时：**上下文重建过** → 必带历史；否则 URL 没变 → 不带历史

### 弹窗清理（每次提问前自动跑）

各家前端进场就爱弹东西：更新日志、功能介绍、满意度调查、Cookie 同意。
这些浮层会**压住输入框和模式开关**，导致后面每一步点击都卡到超时 ——
而且报错只说某元素点不动，**完全看不出是弹窗的锅**，极难排查。

所以 `ask()` 会在三个时点自动清场：进门时、切模式前、发送前。四级降级，
任一级成功即停：

1. **Esc 键** —— 多数 overlay 都监听它，且不会破坏页面状态
2. **站点选择器** —— `providers.<id>.selectors.popup_close`
3. **通用启发式** —— 浮层容器里找"文案像关闭"的小面积可点元素
4. **点遮罩空白处** —— 有些浮层点外面就退

三条硬约束，改这块时别破坏：

- **判定宁严勿松**。候选必须同时满足「面积 < 20000px²」和
  「`aria-label` / `title` / 文案命中关闭词」，宁可漏掉由下级兜底，
  也绝不能把页面上正常的按钮当成关闭键点掉 —— 那种 bug 用户看不懂是怎么回事。
- **失败必须静默**。关不掉弹窗不该让整次提问挂掉，顶多后续点击超时，
  那也是原本就会发生的事。
- **生成答案期间不要调**。此时按 Esc 有可能被站点解读成"中断生成"。

自建自测：造四种典型浮层（ARIA 图标键 / 中文"我知道了" / 无文案无 aria /
只响应 Esc）逐个验证，`python tools/selftest_popup.py`，应当 4/4。
四个用例恰好各自命中一级，跑出来只有 3 个 `heuristic` 也要警惕 ——
说明某一级已经失效了。

## 二、DeepSeek

**模式开关**：`div.ds-toggle-button` 带 `aria-pressed`，用文字"深度思考"定位
（class 是构建哈希，每次发版都变，不能写死）。

**答案容器**（✅ 优先用第一个）：

```
.ds-assistant-message-main-content   ← 真正的回答正文
.ds-markdown                          ← 深度思考模式下有两个，另一个是思考过程
```

⚠️ **坑**：深度思考模式下页面上有**两个 `.ds-markdown`**，一个是思考过程、
一个是正文。只写 `.ds-markdown` 会抓到思考过程，而思考过程里复述了用户提问，
会被"回显检测"误判 → 空转到超时（实测白等 90 秒）。

⚠️ **坑**：会挂引用角标（`…致敏-11`），需要正则清理；单组角标也要清。

**浮层**：进场可能弹「更新日志 / 新功能介绍」等。已内置 `ds-dialog` /
`ds-modal` / `ds-consent` 三类容器的关闭键选择器；改版失效后会回落到
Esc 和通用扫描。肉眼看到关不掉的浮层时，用 `tools/probe_popup.py deepseek`
看它到底叫什么，把 class 补进 `selectors.popup_close` 即可。

## 三、豆包（抓取最难，但能生图）

**模型选择**：输入框右下角 `[data-valid-btn='model-select-action-btn']`，
点开可选「豆包 快速」/「豆包 2.1 Turbo [专家]」。**已无"深度思考"开关。**

**答案容器**：

```
[data-plugin-identifier^='block_type:10000']
```

⚠️ **坑**：`block_type:10000` **用户消息和助手回复都在用**！第一个匹配往往是
用户气泡（带 `justify-end` 和发送气泡背景）。要靠"取最后一个可见的"才能拿到答案。

⚠️ **坑**：思考过程与正文可能都在 `hyc-common-*` 类下，难以区分。

⚠️ **坑**：答完常把 URL 导航回首页，页面内容随之消失。

⚠️ **坑**：**渲染时会在中英文之间自动插空格**（抓回来是"9月30日"，页面显示
"9 月 30 日"）。做文本比对前**必须归一化去空白**，否则永远匹配不上。

⚠️ **坑**：生成式站点，同一问题两次回答的文字**不完全相同**，别指望逐字比对。

**生图**：必须传 `no_mode: true` —— 切到 2.1 Turbo 后它只回文字不画图。
提示词用"帮我生成一张 XXX 的图片"这种直白句式最稳；含"改成/参考"容易被
理解成"改图"而只回文字。图片在图床 `p3/p6-flow-imagex-sign.byteimg.com`，
**页面内 fetch 会被 CORS 挡下**，必须走 Playwright 的网络栈下载。

⚠️ **坑（2026-10-01 实测）**：抓图必须**只取本轮新生成的**。
豆包的图按批出，生成后**留在 DOM 上不消失**；而走"复用页面会话"
（`reset=False`）时，历史消息里的旧图还在页面上。旧实现是"把页面上所有
≥512px 的 `<img>` 按面积排序取前 6"，于是**把上一轮的图又下载了一遍** ——
实测两轮不同提示词（奶龙 / 橘猫）抓回的 4 张图 **SHA256 逐张完全相同**，
而返回 `ok=true`、`images` 有 4 个，看上去毫无异常。

现在的做法：发问前先拍 `img_baseline`（页面上现有的全部图片 URL），
抓图时在 JS 里排除掉。两个容易写错的地方：

1. **排除必须在 `slice(0, limit)` 之前做**（所以写在 JS 里）。先切片再排除的话，
   历史旧图一多就会把新图挤出前 6，表现为"这轮没生成图"。
2. **基线快照要收全**（`limit=500`）。漏一张，它就会被当成新图抓回来。

回归：`tools/selftest_grab_images.py`（用 canvas 造的本地假图，不联网）。
它特意造"8 张更大的旧图 + 2 张较小的新图"——旧图数量必须**超过 limit**，
否则旧实现也能碰巧通过，就测不出这个 bug 了。

另外：**生成几张由提示词决定**。说"画一只柴犬"通常只出 1 张；
说"画 4 张不同姿势的柴犬"就会出 4 张（实测拿到 4 张、哈希各不相同）。

## 四、Kimi

**模型选择**：`[data-testid='model-select-trigger']`（显示"快速 · 进阶"），
点开可选「快速」/「K2.8 Preview」/「**K3**（全能旗舰）」。这就是它的"进阶模式"。

⚠️ 它**没有**独立的"深度思考"开关。界面上那个「深度研究」是联网多步的
**Agent 模式**，会吐检索计划而不是答案，**不要自动打开**。

**答案容器**：`.markdown`（⚠️ 不是 `markdown-body`，写错会一直匹配不上）。

⚠️ **坑**：会把工具栏标签带进正文（表格前混一个"表格 复制"），需清理。

⚠️ **坑**：新版会把提问当 Agent 任务执行，需要用引导词（`prompt_prefix`）按回普通对话。

## 五、腾讯元宝

**模式选择**：它没有开关，是**选模型** —— 点当前模型按钮，菜单里选
「深度思考（深入推理，分析复杂问题）」。

⚠️ **坑**：不要用 `aria-label="切换模型"` 定位（那个元素点不动），
要用可见文字或它自带的 `[data-thinking-mode-switcher-trigger='true']`。

⚠️ **坑**：菜单项是 `<button aria-checked>`，**没有 `role=menuitem`**
（是 `menuitemradio`）；菜单渲染要 >1 秒；若菜单本来就开着，第一次点击会把它
**关掉**，需要再点一次。

**答案容器**：`div[class*='markdown']:not(.hyc-component-deepsearch-cot *)`
—— 思考过程和正文共用同一个类名，只能靠"不在思考面板内部"来排除。

⚠️ **坑**：排除思考面板后，快照为空说明正文还没出来，等待逻辑会继续等（这是对的）。

## 六、通用坑（与站点无关）

1. **`page.is_closed()` 是同步方法，不能 `await`** —— 写错会抛 TypeError，
   被 except 吞掉后**永远判定页面失效**，于是每次调用都重建浏览器。
2. **长文本不要走系统剪贴板**（`navigator.clipboard.writeText` 在非焦点窗口
   会静默失败），用合成 `ClipboardEvent('paste')` + `DataTransfer`。
3. **发送后要校验输入框是否清空** —— 有些站点的"发送"候选选择器会命中
   用户消息气泡（如豆包的 `[data-testid*='send']`），点了等于没点。
4. **过滤条件的下限要留足** —— `len(txt) >= 2` 会把单字符答案（"2"）筛掉，
   进而取到思考过程，再被回显检测放大成超时。
5. **`offsetParent` 对 `position:fixed` 元素返回 null** —— 用它判断可见性会
   漏掉所有弹层/浮层内容。
